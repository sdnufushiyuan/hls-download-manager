# 生命周期与自动选路

`hls-archive.service`持有档案输出锁，先离线预检，再给master/node1/node2分配未完成的区域月份。每节点仅有一个月任务控制器，拥有自己的代理隧道和下载器子进程。控制器退出时清理自己的子进程，不停止其他任务或共享master代理。

master复用8118；计算节点各自建立18119到master8118的SSH本地转发。源码、虚拟环境和ROI通过共享路径访问，最终块落到已核实来源的CIFS NAS。

单块通常最多6次，等待5/15/30/60/120秒。临时故障耗尽返回75，月任务最多额外重试4次、间隔300秒；全批临时故障可由systemd再恢复。永久NAS、文件质量、证书和授权拒绝保持停机，不无限掩盖问题。

## 三个代理组

1. HLS-PREFERRED：Python性能程序核实后的首选。
2. HLS-FAST：原生URL-test，候选Google HTTPS可达性与延迟，300秒更新、200毫秒容差。
3. HLS-ROUTE：生产入口的fallback，30秒检测首选和备用组。

性能程序按周期抽测首选、低延迟候选及轮转候选。最多5个节点各两轮小块，以完整接收耗时比较；内容SHA256不匹配、HTTP错误或无效样本不能获胜。需要两次连续巡检、两轮均改善25%、10分钟间隔；已知失效首选可采用两轮验证的替代线路。若EE初始化/配额不允许测速，保持已有选择，原生健康回退不受影响。

没有对每个节点持续下载大文件，也没有把ping值宣称为实际HLS吞吐。样本大小随内容变化，实际额外流量可从optimizer-state.json的probe_bytes查看。节点列表是用户提供的快照，不负责登录机场、购买节点或绕过Google配额。

## 状态和工期

面板只读systemd、journal及NAS完成记录。实际块速率只计新完成提交，不计缓存复用；候选速率和ETA使用最近最多15分钟的单调时钟窗口。首次需要至少120秒和3个新候选。服务批次变化、计数回退、存储异常或失败状态会暂停/重置估算；单次节点切换后的变化会逐渐反映在滚动窗口中。
