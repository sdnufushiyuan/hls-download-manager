# Earth Engine 请求失败的诊断与续跑

`EEException` 是外层异常类型，不能单靠它判断配额、代理、认证或输入错误。下载器现在沿有界异常链记录 HTTP 数值及固定类别，不输出原始异常、响应内容、签名 URL、令牌。

若 Google HTTP 400 错误体明确属于已知内部错误、计算超时、聚合并发上限或资源限额，执行有界退避。普通无效请求、资产不存在、认证拒绝、内存上限仍终止；不会把所有 4xx 都改成重试。Google 的[调试指南](https://developers.google.com/earth-engine/guides/debugging)区分了这些计算错误，并指出内部错误也可能由脚本逻辑触发；有限重试不等于保证所有内部错误自行恢复。

- 块级最多六次尝试，等待5、15、30、60、120秒；每次刷新下载 URL。
- 暂时网络/计算错误耗尽后保持退出码75；NAS提交错误保持退出码76。
- 并发任务添加场景/块上下文时，必须保留这两类异常，不能转成普通退出码1。
- 月级与 systemd 延迟续跑继续复用原筛选计划、配方、格网、SHA和已完成数据；真正坏块或拒绝访问继续停止保护。

修复后的日志示例：`EEException；http_status=400 category=ee-internal`。这是分类示例，不代表此前没有 HTTP 数值的旧错误已经被证明属于此类。

排查单块时应使用原冻结场景列表、同一选择计划、同一512像元格网、同一代理，将结果写到独立诊断目录，完整读回验证后才考虑补入原目录。目标存在时不得覆盖；补入后重新验证侧车、SHA、格网、QA和有效像元计数。不能用重试掩盖清单范围差异或伪造完成记录。
